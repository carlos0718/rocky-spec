### P4.5 · UI/UX Design System (solo proyectos con interfaz visual)

**Saltear si:** el proyecto es una API pura, CLI, script, o librería sin UI.

El objetivo es generar un design system real antes de escribir código, para evitar el patrón genérico de IA (hero con gradiente azul-violeta, grid de 3 cards, footer de 4 columnas con íconos emoji).

Consultar `.charless/reference/ui-design-guidelines.md` para todos los valores recomendados. El resultado final se guarda usando `.charless/templates/MASTER.md.template` (Paso 4) — un documento propio del área de diseño, tan formal como `SPEC.md` o `AGENTS.md`.

#### Paso 1 — Tipo de producto

```
¿Qué tipo de producto es?
> 1) SaaS / herramienta de productividad
  2) E-commerce / tienda online
  3) Landing page / marketing
  4) Dashboard / admin panel
  5) Portfolio / marca personal
  6) Blog / contenido editorial
  7) Startup / consumer app
  8) Otro
```

#### Paso 2 — Tono visual

```
¿Cuál describe mejor el tono visual?
> 1) Minimalista — limpio, mucho espacio, tipografía como protagonista
  2) Moderno oscuro — dark mode, acentos vibrantes, tech
  3) Orgánico / cálido — terracota, verde, cercano, humano
  4) Profesional / corporativo — azul/gris, confiable, estructurado
  5) Bold / Brutalist — colores llamativos, grids rotos, inesperado
  6) Glassmorphism — translúcido, blur, capas con profundidad
  7) Elegante / premium — mucho whitespace, serif, lujo silencioso
```

#### Paso 3 — Recomendar design system

Basado en tipo+tono, generar la recomendación consultando `.charless/reference/ui-design-guidelines.md`. Mostrarla en este formato:

```
Design System sugerido:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Estilo:         [nombre del estilo]

Paleta:
  Primary:      #XXXXXX  (uso: CTAs, links, acciones principales)
  Accent:       #XXXXXX  (uso: highlights, badges, iconos activos)
  Background:   #XXXXXX
  Surface:      #XXXXXX  (cards, panels, inputs)
  Text:         #XXXXXX / #XXXXXX (primario / secundario)
  Error:        #EF4444
  Success:      #22C55E

Tipografía:
  Headings:     [Font] — weight 600-700
  Body:         [Font] — weight 400, 16px base
  Mono:         JetBrains Mono (código, badges)

Espaciado:      Sistema base-8 (8/16/24/32/48/64/96px)

Componentes clave para este producto:
  • [componente 1 con patrón recomendado]
  • [componente 2]
  • [componente 3]

Anti-patrones — NO hacer en este proyecto:
  ✗ [anti-patrón específico del tipo+tono elegido]
  ✗ [anti-patrón 2]
  ✗ [anti-patrón 3]
  ✗ Íconos emoji en lugar de SVG (Lucide, Heroicons, Phosphor)
  ✗ Animaciones en todos los elementos al hacer scroll
  ✗ Cards con box-shadow negra opaca (usar sombras tenues con color)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
¿Usamos este sistema? (1 = sí / 2 = cambiar color / 3 = cambiar tipografía / 4 = cambiar estilo)
```

#### Paso 4 — Guardar como design-system/MASTER.md

Una vez aprobado, generar el archivo usando **`.charless/templates/MASTER.md.template`** (en P5 se creará la carpeta `design-system/`). Es el mismo tipo de documento formal que `SPEC.md` (nivel "vivo", con Historial de cambios) pero para el área de diseño — separado tanto de `SPEC.md` (producto) como de `AGENTS.md` (ingeniería).

Rellenar sus placeholders con:
- `{{PRODUCT_TYPE}}` y `{{TARGET_USERS}}`: del Paso 1 de acá y de la sección "Usuarios objetivo" ya definida en `SPEC.md` (P1.7) — no volver a preguntar.
- `{{BRAND_ADJECTIVES}}` y `{{BRAND_VOICE}}`: inferir del tipo+tono elegidos (ej. tono "Elegante/premium" → "sofisticado, sereno, sin urgencia"). Si el usuario ya usó palabras propias para describir el proyecto en P1, priorizar esas sobre la inferencia genérica.
- `{{VISUAL_STYLE}}`, `{{VISUAL_TONE}}`, paleta de color, tipografía: los mismos valores acordados en el Paso 3 de acá.
- Border radius, sombras, breakpoints, iconografía, estados de componente, motion: usar los defaults de `.charless/reference/ui-design-guidelines.md` (secciones correspondientes) salvo que el tono elegido sugiera una variante (ver notas de Dark Tech/Glassmorphism para sombras con glow, o Brutalist/Claymorphism para radios). `{{MOTION_DO}}` con 1-2 ejemplos concretos de qué animar en este proyecto puntual (ej. "entrada de cards en el feed, transición entre pasos del checkout").
- Componentes clave y sus patrones: los mismos 2-3 mencionados en el Paso 3.
- Anti-patrones: los 3-5 ya generados en el Paso 3.
- Primera línea del Historial de cambios: fecha de hoy, "Design system inicial (P4.5)", y el commit donde se guardó.

Guardar en `<project-root>/design-system/MASTER.md`.

Avisar al usuario:
> "Guardé el design system en `design-system/MASTER.md`. Es el área exclusiva de diseño del proyecto — separada de `SPEC.md` (qué se construye) y `AGENTS.md` (cómo se construye). Claude Code lo va a usar como contexto cada vez que genere componentes, así todos los colores, tipografías y patrones quedan consistentes."
